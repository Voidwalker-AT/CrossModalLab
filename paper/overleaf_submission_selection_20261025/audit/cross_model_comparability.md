# Cross-model comparability

| Pair of evidence sets | Images / task text / queries / gold | Procedure / parser / split | Model assumptions | Verdict |
|---|---|---|---|---|
| Successful isolated pilot: Smol versus Qwen | Exact same two case IDs, image hashes, complete task-prompt hashes and gold labels; one family p3dev2_2026102403_000 | Development; same leading-space candidates; complete summed teacher-forced sequence LL; candidate argmax, no generated-answer parser | Both pinned at their own exact revisions, frozen base, NF4/double quant/BF16. Native chat/image encodings and compatibility code necessarily differ | DIRECTLY COMPARABLE at task-input/preference endpoint; two dependent cases cannot support a model leaderboard |
| Qwen recent scoring versus its historical same-family standard-prompt generation | Three case/image/standard-prompt identities can match the corresponding frozen-base subset | Summed candidate teacher forcing versus unconstrained greedy generation + historical prefix parser | Same pinned frozen Qwen identity; different output endpoint | PARTIALLY COMPARABLE; cannot pool scores with generation accuracy |
| Smol 0D2 versus Qwen 18-case checkpoint evaluations | Different controlled scenes, entities, case/group counts, task batteries and prompt variants | 36 legacy rows / 30 matched groups, max_new_tokens 20 versus 18 validation cases / six families, historical generation settings | Different model-native processing and model identities | NOT COMPARABLE as an accuracy benchmark |
| Smol Phase 1F versus Qwen behavior | Smol probe features may overlap some exposed contrast families; no matched Qwen neural data | External probe-label prediction versus VLM generated answer | Different models, readouts, selection procedures | NOT COMPARABLE as model ability or causal explanation |
| Earlier failed Phase 3 partial run / failed 108 screen | Frozen plans do not equal completed measurements | Failed combined run / one attempted score, no completed screen | Qwen worker absent from failed screen | NOT COMPARABLE as completed cross-model evaluation |

Direct comparison means matching task-level stimuli and a common endpoint. It does not require two different models to have the *same* revision string: both must have fixed, verified own revisions. Native token IDs and rendered chat templates differ; do not claim byte-identical effective model inputs. Same quantization settings are not proof of equal numerical effects on two architectures.

The successful 12-forward pilot has two gold classes, No and Undetermined. Smol's summed-score preferences were Yes/Yes; Qwen's were No/Yes. Both used candidates ` Yes`, ` No`, ` Undetermined`, including the full two-token abstention answer. These are observed preferences, not calibrated probabilities or generated answers. Absolute likelihood magnitudes are not a cross-model confidence scale. No independent performance estimate or significance test is warranted. Exact scores, hashes, token IDs and worker identities are preserved in `dual_model_audit.json#matched_pilot`; `tables/s2_matched_pilot.tex` is optional supplementary material.

Selection: main text describes complementary evidence streams and explicitly declines a leaderboard. Do not place the 18-case Qwen and 36-case Smol accuracies side by side as if measured on a shared benchmark. The two-case supplement is the only verified common-task comparison selected here.
